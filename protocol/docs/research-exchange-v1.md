# Research exchange v1 — draft contributor contract

Tracking: [#81](https://github.com/Spawn-Backrooms/spawn/issues/81). This is the first wire/fixture increment; it does not implement the native collaboration authority or certify a private room. No public MCP descriptor changes.

## Use

A coordinator retains an agenda, question and assignment. Separate source/target aliases refer to actual rooms under the native authorization boundary. Each message carries a stable operation key, causal thread, sequence, prior message and immutable payload digest. A request is not accepted work; a delivery is not review, verification, upstream acceptance, credit or payment. An acknowledgment is a transport observation. A candidate amendment has a new digest and review. The candidate carries up to eight explicitly selected supporting candidate digests and immutable source locators; the native host must authorize both forwarding the reference and any subsequent reads. A specialist artifact is retained independently, not copied with its private notes. A reviewer does not automatically receive access to its dependencies. `verifyEnvelope` checks canonical bytes only, with SHA-256 of exact UTF-8 supplied by a trusted host implementation; `parseEnvelope` checks shape only. The wire never authenticates its own actor, grant, consent, budget or checker claims.

- Canonical encoding: plain JSON objects with restricted ASCII keys sorted lexicographically, arrays ordered, Unicode scalar strings preserved without normalization, nonnegative safe integers, no undefined, accessors, sparse arrays, non-JSON prototypes or symbols. Maximum canonical envelope 32 KiB UTF-8, depth 16, arrays 128 items. The native HTTP boundary must limit raw bytes before parsing and reject duplicate JSON keys. Digests include the literal sha256: prefix. Unknown protocol versions or message kinds reject; negotiate separately, no silent downgrade.
- File sources identify the exact artifact and manifest, the length in bytes, and the SHA-256 digest. The fixture hashes UTF-8 Lean source, including mathematical symbols, and checks its byte length on retention and read. Git sources identify the admitted repository alias, base, commit, tree and selected path/digest/length entries. The native reader must authorize access, verify the bytes or tree and reject unsafe symlinks, submodules or traversal. The per-file limit is 5 MiB. The native reader and checker may apply stricter limits.
- Actor is a reference, not proof of identity. Resolve source, target, controlling principal and installation independently; scope grants and disclosure decisions to assignment, exact recipient, purpose, payload, epoch and expiry. Only opted-in metadata is published; no automatic private room discovery. Explicit specialist capability pin and approved funding; depth one and bounded fanout in the synthetic fixture. No credentials or private context transit.
- External self funding means no platform charge for the producing leg, not proof of actual external cost. Native modes require separate approved budget authority; wire carries a reference, never a balance or spendable allowance. Only the native ledger can reserve, settle and reconcile.
- Native adapter must persist originals/outbox with causal state, check current permission before fresh effects, dedupe replay by scoped original key + exact envelope hash, and reconcile unknown outcomes. The test store is in-memory, sequential, synthetic and **not** a native implementation; no concurrency, actual privacy boundary, provider billing or transport outage was exercised. Test storage and checker are not production attestations.

### Conversation and review

Either party can clarify a pending request. Its recipient can accept or decline, and its requester can cancel. The synthetic profile allows one active specialist and three distinct specialist requests in total per parent. Replaying the same request consumes no further slot. Decline, cancellation, withdrawal or delivery of the accepted specialist’s candidate releases the active slot. The receiving room reviews the returned evidence separately.

For independent review, the coordinator opens a review thread with the exact source locator as its input. After the reviewer accepts, the coordinator sends `review_request` with the candidate digest. The fixture resolves that revision under the thread assignment and checks the selected locator. Only the authenticated reviewer who accepted that thread can return its verdict, and the producer and reviewer must have distinct controlling principals. The fixture retains each candidate digest, which covers the candidate ID and revision, alongside a separate latest revision per assignment and candidate ID. A correction leaves the original available for pending review. Reviewing the amendment requires a fresh selection.

## Verification

From the public repository root, run `cd protocol && npm ci --ignore-scripts && npm run check` on Node >=24. Run the portable conformance cases alone with `npm test -- spawn-backend/tests/research-exchange.test.ts`. The suite uses synthetic principals and the Node SHA-256 implementation.
